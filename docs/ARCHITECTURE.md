# 구조와 설계

[프로젝트 소개](../README.md)

## 모듈 경계

| 모듈 | 역할 |
| --- | --- |
| `api.py` | 입력 스키마, 업로드·조회·SSE·편집·AI 생성 API, 앱 수명주기 |
| `jobs.py` | 작업 상태, 공유 모델 처리, 대기열 제한, 구독자별 이벤트 방송, 만료·종료 |
| `transcription.py` | Whisper 옵션과 전사 후처리 |
| `diarization.py` | 음성 특징 추출, 화자 수 추정·군집화·라벨 보완 |
| `text.py` | 반복 필터, 발화 병합, 전사 표현 |
| `storage.py` | ID·파일명 검증, 프로젝트·문서 저장·캐시 |
| `llm.py` | Gemini 요청·응답·시간 초과·미완성 결과 처리 |
| `settings.py` | 환경 설정과 공개 기본값 |

복잡한 서버와 별도 프론트 프레임워크를 추가하지 않고, 작은 개인 도구의 기능 경계를 모듈로 나눴습니다. 앱 팩토리는 테스트에서 오디오·AI 처리기를 교체할 수 있어 외부 모델·유료 API 없이 서버 흐름을 검증합니다.

## 처리와 상태

```text
queued → processing → done
                    ↘ error
```

업로드 수신 전에 작업 슬롯을 확보하고 크기·빈 파일·지원 확장자를 확인합니다. 음성 처리는 한 번에 하나만 실행합니다. 다른 요청은 대기하며 슬롯 한도를 넘으면 503과 재시도 안내를 반환합니다.

진행 이벤트는 구독자마다 별도의 제한된 큐로 전달합니다. 느린 구독자의 오래된 이벤트는 최신 상태로 대체하고 완료·오류를 전달합니다. SSE 연결 시 현재 상태를 먼저 전송하고, heartbeat와 연결 해제 시 구독 정리를 수행합니다. 화면은 폴링으로도 완료 결과를 확인합니다.

## 저장 경계

```text
data/
├── uploads/                처리 전 임시 음성
└── projects/<32자리 ID>/
    ├── meta.json           원래 파일명·시간·전사 구간·문서 상태
    ├── audio/source.ext    저장한 음성
    └── docs/
        ├── transcript.md       사람이 저장한 전사
        ├── meeting-notes.md    사람이 저장한 회의록
        └── generated-notes.md  입력·생성 설정 해시와 연결한 생성 캐시
```

프로젝트 저장을 마친 뒤에만 완료 이벤트를 발행합니다. 메타데이터와 문서는 임시 파일에 쓴 뒤 교체하고, 생성·문서 저장 요청은 프로젝트별 lock으로 직렬화합니다. 제목·업로드 파일명을 문서 경로로 사용하지 않으며 존재하지 않는 프로젝트에 저장 요청을 보내도 디렉터리를 만들지 않습니다.

완료 작업이 메모리에서 만료되면 저장된 프로젝트로 결과를 조회합니다. 메모리 상태 만료가 녹음·문서 삭제를 뜻하지는 않습니다. 기존 로컬 프로젝트의 개인 자료를 이 공개본으로 자동 이관하는 기능은 포함하지 않습니다.

## 화자 구분의 한계

전사 구간에서 MFCC·피치 등 음성 특징을 추출해 정규화하고 군집화합니다. 자동 화자 수 추정은 silhouette 점수를 사용하므로 표본 수와 군집 수의 유효 조건을 지켜야 합니다. 특징이 같거나 표본이 적으면 한 화자로 처리할 수 있고, cosine 거리가 정의되지 않는 영벡터에는 다른 거리 기준을 사용합니다.

이는 실제 인물 식별이나 전문 화자 임베딩 모델과 다른 방식입니다. 라벨 번호가 같다는 사실로 사람의 신원을 판단하지 않습니다.
