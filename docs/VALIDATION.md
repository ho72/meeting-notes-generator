# 개선·검증 기록

확인일: 2026-10-07. 기존 로컬 소스의 공개 작업본에서 개선했고 실제 `.env`, 개인 녹음·전사·회의록은 복사하거나 테스트 입력으로 사용하지 않았습니다.

## 수정한 문제

| 기존 동작 | 개선 동작 |
| --- | --- |
| 화면에서 전사를 편집해도 AI는 원래 전사로 생성 | 현재 편집 내용을 명시적으로 전송, 저장 전사·원래 구간 순으로 API fallback |
| 표본 수와 군집 수가 같아 silhouette 계산 실패 가능 | 군집 후보·실제 라벨 수의 유효 조건 확인 |
| 영벡터의 cosine 군집화 실패 가능 | 해당 입력의 거리 기준 보완 |
| SSE 탭들이 하나의 큐에서 이벤트를 가져감 | 구독자별 큐로 방송, heartbeat·연결 정리 |
| 저장을 마치기 전에 작업이 완료 상태 | 프로젝트 저장 완료 후 완료 발행 |
| 원래 파일명·제목을 저장 경로에 사용 | 파일명 정규화, ID 검증, 고정 문서명·음성명 사용 |
| 알 수 없는 ID의 저장 요청이 새 폴더 생성 | 존재하는 프로젝트만 문서 저장 |
| 완료 작업 만료·재시작 후 결과 API가 404 | 저장 프로젝트에서 결과 재조회 |
| 같은 생성 요청이 병렬로 중복 호출 가능 | 프로젝트 lock과 입력·모델·양식·출력 설정별 캐시 |
| provider 원문 오류·URL query의 키 사용 | 키 헤더, 명확한 오류·시간 초과·미완성 출력 처리 |
| 최신 의존성 설치 후 실제 디코딩 실패 | faster-whisper 1.2.1 + PyAV 16.1.0으로 확인·고정 |

## 회귀 검사

Python 3.12.14에서 회귀 테스트 **42개**가 통과했습니다. Ruff 검사·형식 확인과 Node.js 22의 웹 JavaScript 문법 검사도 수행했습니다.

- API 업로드·프로젝트 저장·편집 전사 반영·회수·재조회
- 같은 입력 캐시·입력 및 생성 설정 변경·동시 생성 요청
- 빈 파일·용량 초과·지원 확장자·문서 스키마·프로젝트 경로
- 대기열 제한·단일 오디오 작업·실패한 임시 파일 정리
- SSE 완료 재생·구독자 방송·제한된 이벤트 큐
- 짧은 표본·동일 특징·영벡터·합성 음성 특징 추출
- Gemini 요청 헤더·편집 입력·다중 text part·빈 응답·중단 출력·provider 오류·시간 초과

Markdown 내보내기는 Node.js 테스트에서 편집한 한국어 내용·파일명·Blob 정리 시점을 확인했습니다. 사용한 인앱 브라우저에서는 Blob 다운로드 완료 이벤트를 받지 못해 실제 파일 저장까지의 브라우저 검증은 완료하지 못했습니다.

테스트의 오디오 처리기와 Gemini 전송은 fixture·MockTransport를 사용합니다. 테스트가 통과했다는 이유로 실제 LLM의 요약 품질이나 다화자 인식 정확도가 검증된 것으로 해석하지 않습니다.

## 추가 실행 확인

- 로컬에서 합성한 영어 음성에 CPU·int8·`tiny.en` 모델, 영어 프롬프트와 단일 화자 설정을 사용해 실제 오디오 디코딩·STT·화자 처리 경로를 실행했습니다. 이는 작동 확인이며 정확도 평가가 아닙니다.
- 브라우저에서는 합성 회의 내용의 테스트 처리기로 파일 선택·업로드·전사 표시·편집·저장·회의록 생성 입력 전달·회의록 편집·이전 프로젝트 재조회를 확인했습니다. README 화면은 이 예시이며 실제 외부 모델 결과 화면이 아닙니다.
- PyAV 19 조합에서 faster-whisper의 `metadata_errors` 인자가 실패하는 것을 확인하고, PyAV 16.1.0으로 디코딩 경로를 다시 확인했습니다.
- Starlette TestClient의 httpx 관련 deprecation 안내는 남아 있습니다. 현재 고정 조합의 테스트는 통과하며 실행 장애로 분류하지 않습니다.

실제 Gemini 호출, 한국어 `medium` 모델의 품질, 겹친 음성과 여러 실제 화자의 정확도, GPU·여러 OS·인터넷 서비스 배포는 검증 범위에 포함하지 않습니다.
